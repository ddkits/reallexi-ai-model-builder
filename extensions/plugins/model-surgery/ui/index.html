Start with a supported full model

Llama · Qwen2

Use an unquantized SafeTensors checkpoint with its tokenizer. Merge LoRA adapters into a full model first. Expansion adds capacity; it does not guarantee better quality.

There is no fixed model-size ceiling. Growth happens in whole layers; RAM, disk, architecture, and later training memory determine what this machine can run.

Train the expanded checkpoint

Continual pre-training uses raw text and next-token prediction. Choose a broad corpus for general ability, or a domain corpus with representative general text. Set the budget from pilot evaluations; no universal token count guarantees recovery.

Training streams the file and cycles through it when needed. The history reports token exposures and repeated passes. Start with a small pilot; these default settings are not a model-quality recommendation.

Inspect behavior before using the model

A successful reload proves the files work. Held-out loss and prompt samples help assess behavior; they do not certify broad quality or retained capabilities. Compare against the original base on representative tasks before deployment.

Use the verified output

Each completed expansion or healing run shows its model folder. It contains a standard Transformers configuration, SafeTensors weights, tokenizer, and a model_surgery.json provenance report. Use that folder with Transformers, or select it as a parent here for more expansion or healing.

For a continued domain run, retain a separate general evaluation set and compare both domain performance and general ability. More parameters alone do not establish improvement.

Runs & checkpoint evidence

Every action has a separate run. Cancelling or failing a run preserves its parent checkpoints. Partial output is never offered as a verified model.
